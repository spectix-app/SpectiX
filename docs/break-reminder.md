# 番茄倒计时：连续工作计时 + 「该休息了」

**改 `BreakReminder.swift`、header 的 🍅 芯片 / 横条面板、`"rest"` 状态色、toast 的常驻规则前读这份。**

## 它管什么

这一块量的是**人**，不是 Claude：你在电脑前连续待了多久。四个状态、一个时钟：

| 状态 | 芯片 | 横条 | 怎么进 / 怎么出 |
|---|---|---|---|
| `working` | 🍅 48:12（番茄淡底） | 淡红底，按钮 `现在休息` 是**绿**的 | 开始用 AI（任一会话进入运行）或点「开始倒计时」进；到 0 → overtime；点「现在休息」→ resting |
| `overtime` | 🍅 −03:12（**红字** + 淡番茄底 + 荧光呼吸，见下） | 番茄红渐变、白字、荧光呼吸 | 同一个 deadline 继续往负走；右上角弹番茄横幅 + 完成提示音（**时机见下**），每隔一个工作时长再弹一次 |
| `resting` | 🐈 09:41（绿） | 绿底 + **绿色荧光呼吸**（比超时那档淡一半），猫咪伸懒腰照片呼吸缩放，按钮 `结束休息` 是**红**的 | 点「现在休息」或**走开被判成休息**进；休息倒计时到 0 → idle；**点「结束休息」直接 → working 开始倒计时**（提前回来就是回来了，不再停在「休息好了？」等第二次点击，2026-09-24 用户定） |
| `idle` | 🍅 --:--（绿） | **绿底**（还在休息这一族），戴眼镜的猫，「休息好了？」+ **红**按钮 `开始倒计时`；刚休息完时说明行写「已休息 N 分钟」（从休息开始算、一直往上涨） | 点按钮，或 AI 有新动静自动开始 |

「AI 有新动静」= `notifyTransitions` 里任一行**进入** `working`（needs / paused / idle / done → working）。App 刚启动、已经有会话在跑时宽松一次：直接起跑（`everStarted` 之前）；之后的重启都要等新动静，这是用户要的「休息完要主动回来」。

**没按按钮就走开也算休息**（v1 的在场判定原样保留）：5 分钟无键鼠且没会话在跑、或有会话在跑但 20 分钟无输入、或轮询断了 5 分钟以上（合盖睡眠）→ 段落收尾进「今天总计」，**进 resting（休息开始时刻记成最后一次键鼠输入）**，满休息时长才到「休息好了？」。以前直接回 idle，超时里读了 5 分钟东西就看到「休息好了？」，可人根本没休息（2026-09-30 用户报）。这种**推断出来的休息**遇到 AI 新动静会直接回到倒计时（和以前的 idle 一样）；**按按钮的休息**则跑满全程，AI 动静不打断。有会话在跑时 20 分钟才算走，是因为盯着 Claude 跑一个长轮次不是休息；没这条对 Claude Code 用户来说提醒永远不响。

**横条右上角、✕ 左边有个小图标按钮：倒计时 ⇄ 正计时**（`AppSettings.breakCountUp`，记住选择）。倒计时显示「离休息还有」，正计时显示「已经工作了多久」；休息态同理（剩余 / 已休息）。图标本身表示当前模式：`timer` = 倒计时，`stopwatch` = 正计时。**芯片和横条读同一个数**（`BreakReminder.displaySec`），所以两边不可能对不上。它放在角落不放按钮行，是因为工作态那行已经有两个按钮，再加一个会把副标题挤成省略号。

**点横条上的大数字弹时长菜单**：平时是番茄时长（25–120 分），休息中是休息时长（5–20 分），和设置页是同一个设置。当前这一轮当场按新时长重算——超时中调长会回到倒数并重新挂上「到 0 自动弹」；休息的结束时刻由 `restStart + 休息时长` 现算，所以调短到已过的时刻会在下一次轮询结束休息。

`+10 分` 一轮只能按一次（调研结论：无限推迟会把提醒推到失效）；从 overtime 按会把时钟拉回正数、再次到 0 会再弹。

## 配色规则（2026-09-14 用户定，改任何一处颜色前先读）

**底色 = 你现在所处的状态；主按钮 = 按下去会进入的状态。**

· 工作中 / 超时 → 底是红的，按钮「现在休息」是**绿**的  
· 休息中 → 底是绿的，按钮「结束休息」是**红**的  
· 「休息好了？」→ 仍算休息这一族，底也是**绿**的，按钮「开始倒计时」是**红**的  

⚠️ **浅色底的三档（工作 / 休息 / 休息好了）必须自己定死深色文字**，不许用 `.labelColor` / `.secondaryLabelColor`：那两个在深色模式下翻成白色，而底色是固定的淡红 / 淡绿，结果就是白字压浅绿看不见（2026-09-14 实测）。只有超时那档的红底配白字。

绿底上的按钮用 `tomatoDeep` 而不是 `tomato` —— 后者是 Claude 的赤陶色，挨着绿色会读成橙色，不是用户要的红。

推论：**按钮永远不和它所在的底同色**。以前工作态是红底配红按钮、休息态是绿底配绿按钮，按钮就退化成了装饰而不是出口。「+10 分」是例外 —— 它让你继续工作，属于红，所以在红底上只能用半透明白，否则看不见。

## 横幅什么时候弹（2026-09-11 改）

**到点不一定当场弹。**这一刻只要有会话在跑、或有会话在等你确认（`busy`），横幅就先**压住**（`heldBanner`），等到第一次「没有在跑也没有在等你」的轮询才弹 —— 那才是能起身的时刻，跑到一半告诉你去休息你也走不开，而且会把「需确认」那条红横幅压在下面。

**压住有上限：10 分钟**（`holdCap`）。无人值守跑一整夜时机器可能永远不安静，没这个上限提醒就被永久吞掉了。横条和芯片的红色 / 荧光**不受影响**，时钟一到 0 立刻变红。

面板的自动弹开（`autoShowPending`）和横幅同一时刻触发，所以两者永远一致。

## 横条面板怎么挂

面板 `BreakPanel` 放在 `HeaderStatsView` 里、2×2 指标格正下方，**两个宿主自动都有**。默认高度 0 + hidden；展开只有两条路：点芯片（toggle）/ 时钟过 0 自动弹一次（`autoShowPending`；用户按 ✕ 后 `dismissed` 挡住本轮再弹）。**倒计时一开始（进入 working）横条自动收起**——它是给到点和休息用的，看数字走有芯片；点芯片可以临时看一眼（`peeking`），下次点或 ✕ 再收。高度变化走 `HeaderStatsView.onLayoutChange`：popover 调 `resize()`，主窗口调 `adjustWindowHeight()`。主窗口的芯片在标题行（归 `MainWindowController`），点了去 toggle 共享 header 里的面板。

大数字和它下面那行说明装在同一个容器里（`textBlock`）**整体居中**。别改回「各自贴着中线」—— 24pt 的数字和 10.5pt 的说明绕同一条边排，数字看着明显偏上（2026-09-11 用户提）。改完用下面的脚本出图，量出来的墨迹中心应该落在横条中线 ±2pt 内。

芯片 `BreakChip` 自己画胶囊，不走 `CapsuleLabel`——超时态要红字 + 淡番茄底 + 阴影呼吸，状态色系统给不了。**超时芯片是红字（`BreakLook.overInk`，深色外观换亮一档的红），不是实心红底白字**（2026-09-30 用户报「标题栏的 🍅 计时超时后白字看不清」；离屏预览里红底白字是清楚的，真机为什么看不清我没查实 —— 疑是芯片底下主题的 `ChipShellView` 盖住了那层番茄色。红字不依赖那层底色，所以两种情况都读得清）。「休息好了？」的「已休息 N 分钟」超过 2 小时就不显示（合盖一夜不算休息 720 分钟），退回「今天共 X」。

**闪烁 = 阴影透明度 0.8s 往返（1.6s 一个来回）**，远低于 WCAG 2.3.1 每秒三次的光敏线；别改快。

⚠️ **荧光是 `surface` 上的阴影，两条硬约束**（2026-09-11 踩过：休息态出现一个绿色直角方块）：
· 横条**不许裁自己**——用 `letShadowsEscape()`，光设 `masksToBounds = false` 不够，macOS 14 起 NSView 自己也裁（`clipsToBounds`）。收起靠 `isHidden`，不靠裁切
· 模糊半径受**阴影预算**管：`|offset| + 2×blur ≤ 18`（见 `docs/design-system.md`）。现在是超时 9、休息 8。超预算的阴影会被外层容器切成直线，这正是那个方块的来历

## 和 toast 系统的三处约定

- 状态串 `"rest"`：不是会话状态，`Status.accent / fill` 里直接短路成 `claudeOrange`，**没有主题槽位、不进用户配色**；`Status.label` 给「休息 / Rest」；`Status.bucket` 不认它。
- path 固定 `"!break"`：`ToastManager.retain` 见 `!` 前缀直接跳过——它不属于任何会话，否则 6 秒后会被当孤儿清掉。
- **不常驻**：`sticky = needs`，rest 和 done 一样 8 秒后自己淡出、没有 ✕（2026-10-04 用户定：芯片和横条到点就变红，横幅只负责提醒一下）。点它 → 打开主窗口、展开横条、横条**放大一下**（`BreakPanel.pop`，1.04 倍 0.45 秒，延后 0.25 秒等窗口到前台），再关横幅。
- **进休息就收横幅**：`startRest` 发 `BreakReminder.restStarted`，`AppController` 收到当场 `dismiss("!break")` —— 只靠轮询会慢几秒。`maybeRemindBreak` 每次轮询照样兜底：状态不是 working / overtime 就收。

## 主按钮 1.5 秒防连点

横条的主按钮位置不变、含义会翻转（现在休息 → 结束休息 → 现在休息，开始倒计时 → 现在休息），所以双击或者手快多点一下，两个动作会一起执行：刚进休息就被结束，横条直接跳到「休息好了？」（2026-09-18 用户报）。`BreakPanel.press` 在上一次按下后 1.5 秒内再按一律忽略。别删。
