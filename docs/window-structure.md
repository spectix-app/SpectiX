# 窗口结构：5 合 1 tab（改导航前必读）

以前会话 / 最近项目 / 统计 / 设置各开一个独立 NSWindow；现已合并为**单一主窗口 + 底部集成 tab 栏**（方案 6，`design/main-window-merge-alternatives.html`）。

- **主窗口**（`MainWindow.swift` `MainWindowController`）：header 行 = wordmark（刷新钮已删——列表靠 2.5s poll 自动刷新，手动刷新无必要）；下方 5-pane 容器（hide/show 切换，非 NSTabView）；底部挂 `BottomTabBar`（`BottomTabBar.swift`，flat icon+label 5 tab，会话 tab 带红 needs badge，各 tab 占 ⌘1–5 局部快捷键）。`MainTab` 枚举 = `sessions/stats/recent/skills/settings`。深链 API `showMainWindow(tab:)`。
- **5 个 pane**：会话 = statsHeader + listView（summary 只此 tab 显）；`RecentProjectsPane`（`RecentProjectsWindow.swift`）/ `StatsPane`（`StatsWindow.swift`）/ `SettingsPane`（`SettingsWindow.swift`）—— 均由旧的 `*WindowController` 抽成 `NSView`，外包 NSScrollView。旧独立窗口类已删。**技能**（`SkillsPane.swift`，T320，2026-09-24）列出本机全部 Claude / Codex 的 skill 与 agent 及使用次数，切进来时 `paneDidAppear()` 触发一次增量扫描，细节见 [skills-catalog.md](skills-catalog.md)。
- **技能 tab 刻意不进 popover 底栏**：popover 最窄 384pt，底栏已是「警告 + 4 个入口」，再加一个标签就挤不下；它是浏览页，不是随手要点的入口。⌘ 快捷键因此变了：技能占 ⌘4，设置从 ⌘4 挪到 ⌘5。
- **红叉 = 隐藏窗口，不退出**（改窗口生命周期前必读）：菜单栏 App 收起唯一窗口 ≠ 用完了，所以主窗口红叉 → `MainWindowController.windowShouldClose` 做 `putAway()` + `return false`——窗口对象和各 pane 状态整份留着，下次 `showWindow` 秒开。退出 App 走右键菜单栏图标的「退出 SpectiX」（唯一入口，见下）。languageDidChange / themeDidChange 的 `closeForRebuild()` 走 `NSWindow.close()`（**不经** `windowShouldClose`），才是真拆卸重建——利用这条差异区分「用户点红叉」vs「内部重建」。
- **窗口位置/大小持久化**（改窗口 frame 前必读）：`setFrameAutosaveName` 在本窗口（透明标题栏 `titleVisibility=.hidden` + `titlebarAppearsTransparent` + `backgroundColor=.clear` + NSWindowController 组合）**静默失效**（UserDefaults 查不到 `NSWindow Frame …`），故改**手动持久化**：`AppSettings.mainWindowFrame`（`NSStringFromRect`）在 `windowDidMove` / `windowDidEndLiveResize` 时存当前 frame（带 `isVisible` guard 防拆卸/恢复期 programmatic setFrame 误写），init 里有保存值就 `setFrame` 恢复、否则 `center()`。**默认尺寸 476×847**（首启动那次照屏幕可见高度收一下再居中）。content-fit（`adjustWindowHeight`）仅在 `!mainWindowUserSized` 时改高度——而**首启动的 `center()` 分支当场把 `mainWindowUserSized` 置 true**，所以默认高度不会被内容贴合吃掉（实测不置就会立刻缩到 567）；此后 resize 同样锁定。改默认尺寸时记着这两件事是绑在一起的：只改 `contentRect` 而不保留这个置位，高度改了等于没改。
- **收起窗口 = alpha 停泊，绝不 `orderOut`**（改 `putAway` / `showWindow` 前必读）：`orderOut` 会让窗口**丢掉 Space 归属**，下次 `orderFront` 把它重新落座到「当时是哪个桌面就哪个桌面」——这正是「在桌面 2 收起、再打开却出现在桌面 1」的成因。所以 `putAway()`（红叉 + 黄钮 + ⌘M 共用）只做 `alphaValue = 0` + `ignoresMouseEvents = true`（透明窗口不能吃点击）+ `NSApp.deactivate()`（orderOut 原本自带的「把前台还回去」得手动补），窗口始终 ordered-in、始终绑在原桌面；`MainWindowController.showWindow` override 负责解除停泊。FocusRing 的浮层同理同因（见其 alpha-park 注释）。
  - **`isVisible` 不再等于「用户看得见」**：停泊中的窗口 `isVisible` 恒为 `true`，所以一切「用户在看吗」的判据一律问 `MainWindowController.isShown`（= `isVisible && !isParked`），别再直接读 `window.isVisible`——poll 重载、frame 持久化、`focusSession`、Dock reopen、主题重建的 `wasVisible` 都靠它。
  - **回来 = 切桌面，不是搬窗口**：`showMainWindow` 在 `showWindow` 前先 `switchToSpace(of: windowNumber)`（复用跳转那套 CGS 私有符号，符号缺失即 no-op 退化成旧行为），不依赖 macOS「切换 App 时切到有该 App 窗口的空间」那条系统偏好——用户关掉它同样会把窗口拽到当前桌面。
  - **⌘Tab / Dock 兜底**：这两条路径不经 `showMainWindow` 就激活 App，AppKit 会把停泊窗口「带到前面」（切过去却只看到全透明的它），故 `applicationDidBecomeActive` 发现 `isParked` 就补一次 `showMainWindow`。popover 刻意从不 `NSApp.activate()`，所以不会误触发。
  - **跨进程仍无法恢复**：退出 App 再启动是新窗口、没有 Space 记忆（只有 frame 存在 UserDefaults 里），开在当前 Space。上面这套只覆盖同一进程内的收起 → 再打开。
- **设置 pane 生命周期**：ring 预览 / 权限轮询只在设置 tab 可见时跑——`showTab(.settings)` 切入触发 `paneDidAppear()`、切走触发 `paneDidDisappear()`、红叉隐藏（`windowShouldClose`）与 `closeForRebuild()` 各自兜底停（幂等）。
- **popover 底栏同构**（变体 A，`design/menu-popover-scheme6.html`）：`MenuPopover.swift` footer = flat 底栏，4 个 `TabItemButton`（复用 BottomTabBar 的按钮）深链到对应 tab（会话入口带 needs badge），⚠️ 权限修复按需在最左（`warn` 黄、icon-only）。header 无刷新/退出按钮（均已删）——**退出 App 唯一入口 = 右键点菜单栏图标弹出的「退出 SpectiX」单项菜单**（`main.swift` `togglePopover` 检测 `.rightMouseUp` 临时挂 `statusItem.menu`）。入口 wiring：`onOpenWindow/Stats/Recent/Settings` → `openMainWindow/openStats/openRecentProjects/openSettings` → `showMainWindow(tab:)`。
- **popover 的隐形锚点每次重建，绝不跨次复用**（改 `togglePopover` 或锚点前必读）：面板不挂 status button（button 的窗口随菜单栏滑动 → 系统每帧重新定位，理由见 `main.swift` `popoverAnchor` 上方注释），而是挂一个 24×1 全透明 panel。这个 panel **每次打开新建、`popoverDidClose` 里置 nil 丢掉**。起因：2026-08-12 一个连跑 20 小时、中途插拔过外接屏并睡过多次的进程，点图标完全不出面板，而日志每次都记 `isShown=1`，重启进程立刻恢复；当时进程内唯一的长寿窗口就是它，同期 FocusRing 那些**每次新建**的浮层照常显示。因果**没有证据、只有这条相关性**（别写成已证实），但每次多建一个空 panel 的代价小到不值得权衡。
  - ⚠️ **别再拿 `CGWindowList` 去验证「我的窗口还活着吗」**（2026-08-12 实测）：本进程自己的窗口**根本不进那个列表** —— 24×1 和 410×854 × 全透明和不透明 × 按 id 查（`CGWindowListCreateDescriptionFromArray`）和全量屏上扫（`.optionOnScreenOnly`），组合全为空，而这些窗口 `isVisible=1` 确实在屏上；SpectiX 里也复现（面板正常显示时锚点查询恒为「不存在」）。据此加过一道「系统不认就重建、两次不认就退回主窗口」的闸门，结果对每一个健康窗口都判死刑，面板 100% 打不开，比原 bug 更严重。**它对活窗口和死窗口的回答一模一样**，既不能当闸门也不能当诊断。目前 App 内部**没有任何已知办法**区分锚点死活（`isVisible` / `windowNumber` / `popover.isShown` 全都照常返回健康值），所以修法只能是绕开判据（无条件重建），不是加判据。
  - popover 那面还要记得：`HeaderStatsView.layout()` 里算「两个配额胶囊塞不塞得下」的 `lead` **含徽章宽度**，否则警告徽章会把胶囊挤出右边缘而不是触发折叠。
- 已删死代码：`SegmentedPill`（旧 header 三钮胶囊，合并后无使用方）+ 连带 `GlassButton.bare` 参数及分支（bare 唯一用户是 SegmentedPill）。
